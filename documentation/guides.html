Seven things you will actually do, in order

Each guide is a sequence of steps with the code you would write. The examples are taken from the reference application, an end-to-end-encrypted messaging client split across a main thread and a worker, so every snippet has a real home in prototype/e2/src.

Guide 1

Define and implement a service

  1. Write the contract as an interface, and the key with the same name. 
    export interface Crypto {
  readonly seal: (inbound: Inbound) => Fx<Envelope>
  readonly open: (envelope: Envelope) => Fx<Inbound, CryptoError>
}
export const Crypto = service<Crypto>()('Crypto')
  2. Implement it with make. Yield what you need; that is the dependency declaration. 
    export const CryptoLive = Crypto.make(function* () {
  const config = yield* Config
  const cipher = (text: string, shift: number) => /* … */
  return {
    seal: (inbound) => sync(() => ({ ...inbound, ciphertext: cipher(JSON.stringify(inbound.payload), 1) })),
    open: (envelope) => gen(function* () {
      if (envelope.ciphertext.startsWith('!')) return yield* err(new CryptoError(envelope.id))
      return { ...envelope, payload: JSON.parse(cipher(envelope.ciphertext, -1)) }
    }),
  }
})
// Provider<'Crypto', 'Config', never>
  3. Check the parameter types came from the contract.

    Hover inbound in seal: it is Inbound with no annotation, because the contract bounds the returned object. A method that reaches for a service the contract does not mention is rejected here, not discovered by a caller.

  4. Use it from anywhere, without threading it through. 
    const absorb = (envelope: Envelope) => gen(function* () {
  const crypto = yield* Crypto
  const inbound = yield* crypto.open(envelope)
  return yield* ingest(inbound)
})
// Fx<readonly Message[], CryptoError | DomainError, 'Crypto' | …>
Guide 2

Compose an application at one root

  1. List every provider once. Order does not matter. 
    const rt = await runtime([
  Config,                      // a defaulted service goes in as itself
  NetworkLive,
  LocalStoreLive,
  MediaStoreLive,
  ServerFetchLive,
  CoreValidationLive, MediaStageLive, SearchIndexLive, SearchStageLive,
  PreStagesLive, PostStagesLive, CategorisersLive, HandlersLive,
  MpsLive, SendLive, ReceiveLive,
])
  2. Let the compiler close the list.

    Remove SearchIndexLive and the next line fails with Property 'run' does not exist on type '"e2: missing service SearchIndex"'. The check folds in every provider's own needs, so a service nothing in your program mentions directly is still caught.

  3. Decide the startup policy here, and nowhere else. 
      lazy(CryptoLive),   // ratchet set up on the first seal or open
  lazy(MpsLive),      // built by the first read, send or receive - whichever comes first
  lazy(SendLive),     // nothing until the user sends
  ReceiveLive,        // a subscription can arrive at any moment

    A lazy provider's construction failure reaches its first user as a ProviderFailed defect instead of failing startup. Use it for services genuinely optional at boot.

  4. Look at what actually happened. 
    rt.graph()
// {
//   Mps:  { status: 'done',  lazy: true,  demanded: ['LocalStore', 'ServerFetch', 'Crypto', 'MPS/PreStages', …] },
//   Send: { status: 'empty', lazy: true,  demanded: [] },   // nobody has sent yet
//   …
// }
  5. Close it in reverse.

    await rt.close(), or await using rt = await runtime(…). Every acquire releases most-recent first, and every batch flushes what is pending.

Guide 3

Test with doubles

  1. A double is a provider for the same key. 
    const offline = Network.of({
  send: () => fail(new NetworkError('offline')),
  inbound: () => async_(() => undefined),
  simulateIncoming: () => ok(undefined),
  sentCount: ok(0),
})

const result = await run(program, [Config, offline, LocalStoreLive, CryptoLive, MpsLive, SendLive, /* … */])
  2. Prefer make for a stateful double.

    Store.of(new Map()) is one map shared by every runtime that lists it. Store.make(function* () { const rows = new Map(); return { … } }) is a fresh map per build.

  3. Assert on behaviour through the services.

    The reference suite reads LocalStore.count, LocalStore.writes and ServerFetch.fetchCount to assert "a failed send leaves no phantom row" and "fifty envelopes are one write". Contracts that expose their counters are testable across a worker for free.

  4. Use runSync when nothing suspends.

    Synchronous providers and a synchronous program run in a plain function call. Reaching an asynchronous operation produces Die(AsyncBoundary), never a hang.

Guide 4

Open a database lazily, once

  1. Wrap the acquisition in memo, inside the provider that owns it. 
    const db = yield* memo(
  acquire(() => openMessages('messages-' + config.userId), (store) => store.close(), (reason) => new IdbError(reason))
)
// db: Fx<IdbStore, IdbError> — no dependencies, not opened yet
  2. Make every read and write yield the handle. 
    get: (id) => gen(function* () {
  const store = yield* db
  return yield* fromPromise(() => store.get(id), (reason) => new IdbError(reason))
}),

    The first read opens the store; concurrent first reads share the one open; later reads find it open. The provider itself constructs synchronously and cannot fail; the open's failure belongs to the read that triggered it, where the contract already says IdbError.

  3. Want it warm? Say so at the memo, not at the root.

    memo(acquire(…), { eager: true }) starts the open in the background at construction. Reads arriving before it settles wait; reads after do not. Nothing else changes.

  4. Let teardown close it.

    The acquire registered on the runtime scope when the memo was created, not on the request that happened to read first, so rt.close() closes it in reverse order with everything else.

Guide 5

Coalesce writes without changing the API

  1. Create a batcher where the writes happen. 
    const writer = yield* batch(
  (messages: readonly Message[]) => sync(() => { writes += 1; return messages }),   // one transaction
  { maxSize: 500 }
)
  2. Make the row visible immediately, and enqueue the write. 
    put: (message) => gen(function* () {
  const rows = yield* db
  rows.set(key(message), message)
  yield* writer.enqueue(message)
  return message
}),

    Visible-before-durable is what lets a reaction find a message that arrived in the same batch. Keep the buffer in the store, where the readers are.

  3. Expose flush and a counter, and let the scope flush at close.

    flush: writer.flush for callers that need durability now. The batcher's own finalizer flushes at shutdown. A test asserts writes === 1 after fifty puts in one synchronous run.

  4. Use add when the caller needs its result.

    add(item) waits for the batch and receives its own element of the result, by position, which is the DataLoader shape. It parks, so it needs an asynchronous entry point.

Guide 6

Put a service in a worker

  1. Make sure every member of the contract can cross.

    An Fx value, a method of cloneable arguments returning an Fx, or a trailing-callback method returning Fx<never, E>. If a member cannot, the compiler names it. Either change its shape or leave that service in the worker.

  2. In the worker, build the runtime and serve the keys. 
    const rt = await runtime([/* … */])
serve(rt, [Mps, Send, Receive, SearchIndex, LocalStore], codec)
  3. On the main thread, link the worker and remote the keys. 
    const Worker = link('MpsWorker', new URL('../worker/main.ts', import.meta.url), codec)
await runtime([MessageListLive, Worker, ...remote(Worker, [Mps, Send, Receive])])
  4. Write the consumer as if nothing crossed. 
    export const MessageListLive = MessageList.make(function* () {
  const mps = yield* Mps
  const send = yield* Send
  const receive = yield* Receive
  return {
    compose: (threadId, body) => send.send(threadId, { kind: 'text', body }),
    live: (threadId) => receive.forThread(threadId, (message) => render([message])),
    // …
  }
})
  5. Keep the codec honest.

    Every error class that can cross needs a case in decodeError. That file is the whole protocol now, so it is short enough to review.

Guide 7

Extend the message pipeline without touching it

MPS owns the shape of processing and nothing else. It depends on four extension points, services nobody gives a default to, and the composition root fills them.

  1. Open the unions from your own file. 
    declare module '../domain.ts' {
  interface PayloadMap   { pin: { readonly targetId: string } }
  interface DirectiveMap { PinMessage: { targetId: string; threadId: string; by: string } }
}
  2. Write the categoriser, the handler, and any stage the feature needs.

    Plain functions and plain values. A stage that needs a service is a service of its own, so it can be swapped in a test and shipped by a team that owns neither MPS nor the root.

  3. Watch the root stop compiling.

    CategoriserTable and HandlerTable are exhaustive over the open maps, so opening a union makes the registries incomplete. The gap cannot reach runtime.

  4. Wire it in, in one file. 
    export const CategorisersLive = Categorisers.of({ ...coreCategorisers, pin: pinCategoriser })

export const HandlersLive = DirectiveHandlers.make(function* () {
  const local = yield* LocalStore
  return { ...coreHandlers(local), PinMessage: pinHandler(local) }
})

export const PreStagesLive = PreStages.make(function* () {
  const core = yield* CoreValidation
  return [...core, pinPolicyStage]     // ordered after the built-in rules
})

    Adding the pin kind touched three files and none of them was mps.ts.
