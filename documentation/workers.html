e2 · workers

A service key is the same key on either side of a worker

Because a service is looked up by name and its contract is TypeScript, a service can be served across a worker boundary by key. The worker serves it; the main thread gets a provider for the same key from remote; a consumer does yield* Mps and cannot tell which side it is on. The bridge that does this lives in the reference application, not the core, since it is platform code.

serve(rt, keys, codec)
exposes the listed services over the worker's message port. Builds nothing; each service is demanded from rt on its first remote call, so a lazy() one stays lazy. Compile-time checks: every key is servable, and every key is provided by rt.
link(name, url, codec)
a worker as a service with a default: opened when first needed, terminated when the runtime closes. Every remote key for this worker shares it.
remote(Worker, keys)
a provider per key, each depending only on the link. The same servable check as serve.
What can cross

A member is servable if it is one of three shapes

ShapeExampleServed as
an Fx valuecount: Fx<number>a zero-argument call
a method of cloneable arguments returning an Fxget(threadId, id): Fx<…>a call
a method whose last argument is a callback and which returns Fx<never, E>forThread(id, onMessage): Fx<never, E>a stream

Anything else cannot: a plain value, a method returning a plain value, a callback anywhere but last, a callback on a method that completes. The diagnostic names the service and the member, and it fires at the entry of the list that is wrong.

TS2322a plain value in the contract
Type 'Service<"Crypto", Crypto>' is not assignable to type 'Service<"Crypto", Crypto> & "e2: Crypto.deviceId cannot cross a worker boundary - only Fx values, Fx-returning methods, and trailing-callback streams can"'.
TS2345serving what the runtime does not provide
Argument of type 'Runtime<"Config" | "Crypto">' is not assignable to parameter of type 'Runtime<"Config" | "Crypto"> & "e2: serve: Mps is not provided by this runtime"'.

Three members in the reference application failed the rule when it was introduced, and each fix improved the contract. Mps.describe returned a plain object and became an Fx value. Network.onInbound returned an unsubscribe function and became inbound(onBatch): Fx<never>, which Receive now forks, so unsubscribing is structural. Crypto.deviceId is a plain value, and Crypto is simply not served.

Streams

A trailing callback and a never-completing effect

e2 has no Stream. A subscription is an effect that never completes on its own, delivers each value to a callback, and runs until interrupted. Fork it to subscribe, interrupt the fiber to unsubscribe, which structured concurrency does for you when the parent finishes. The bridge recognises the shape on both sides: on the main thread a trailing function argument selects the stream path; in the worker serve supplies the callback and turns each invocation into an event reply, until the caller's fiber is interrupted and a cancel crosses back.

// the contract, unchanged by the boundary
readonly forThread: (threadId: string, onMessage: (message: Message) => void) => Fx<never, DomainError>

// the consumer, on the main thread
const subscription = yield* fork(receive.forThread('thread-a', (message) => render([message])))
// … later, or when the parent ends:
yield* interruptFiber(subscription)
The codec

The one thing a contract cannot say

Structured clone drops prototypes. A NotFound thrown in the worker arrives on the main thread as a plain object, and something has to rebuild it. That is the codec, { encode, decode }, passed to both serve and link, and it is the application's. It is hand-written, one case per error class, and it is exactly the kind of code that rots. Effect's Schema.TaggedRequest generates the equivalent; that is a genuine advantage of carrying a schema, noted plainly.

Under the hood

No manifest, no glue

  • The remote object is a Proxy. Every member you read on it is an object that is both callable and a Suspend instruction, so local.get(a, b), yield* local.count and Fx.map(f)(local.count) all work without the client knowing which members are methods and which are values.
  • The worker decides per request: it does yield* Key, looks at the real member, and calls it or yields it. A member that does not exist is a defect with the service and member in the message.
  • Every request is a forked fiber in the worker, so cancellation is uniform: a unary call and a stream are interrupted the same way, and their finalizers run.
  • The proxy's round-trip cost is not measurable against the transport: 0.020 ms before, 0.023 ms after, in the reference bench.
Why Effect cannot mirror this A Context.Tag carries no runtime shape, and Effect's position is Schema at every boundary, so it keeps one TaggedRequest class per method plus a handler per request. That is safer on an untrusted wire; on a same-origin worker it costs a class per method. Both positions are reasonable. This one is e2's.
